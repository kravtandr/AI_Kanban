# ADR-0005: Интеграция LLM

- **Статус**: accepted (модель утверждена владельцем 2026-07-22; дополнено 2026-07-23 и 2026-07-26)
- **Дата**: 2026-07-22

## Контекст

LLM категоризирует и оформляет задачи (FR-5.x). Нужны: надёжный структурированный
вывод, деградация без блокировки CRUD, контроль стоимости.

## Решение

- Официальный SDK `anthropic`; модель по умолчанию **`claude-opus-4-8`**,
  переопределяется env `ANTHROPIC_MODEL` (например, `claude-haiku-4-5` для экономии).
- Structured outputs: `client.messages.parse(..., output_format=TaskDraft)` — ответ
  всегда валидирован Pydantic-схемой `TaskDraft`.
- Стабильный системный промпт (prompt caching); дата и список проектов/тегов — в
  user-сообщении.
- Таймаут 15 с, `max_retries=1`; любая ошибка → fallback-черновик (сырой текст → title,
  проект Inbox), UI/MCP получают `ai_ok=false` и продолжают работу.
- Учёт токенов — таблица `llm_usage` на каждый вызов.
- Вызовы только по явным действиям (draft/enhance/auto_format), фоновых прогонов нет.

## Дополнение 2026-07-23: второй провайдер — self-hosted OpenAI-compatible

По запросу владельца добавлен провайдер `openai` (env `LLM_PROVIDER`) для
self-hosted моделей через любой OpenAI-совместимый `/v1/chat/completions`
(конфиг: `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`). Структурированный
вывод обеспечивается промпт-инструкцией «только JSON» + извлечением JSON из
ответа (срезаются `<think>`-блоки и code fences) + валидацией той же
Pydantic-схемой `TaskDraft`. Невалидный JSON = штатная деградация FR-5.5.
Один и тот же интерфейс `_call_model`; выбор провайдера не меняет остальной код.
Текущая конфигурация владельца: qwen36-35b-a3b-think на собственном сервере,
таймаут поднят до 90 с (thinking-модель).

## Дополнение 2026-07-26: модель, таймаут и температура self-hosted провайдера

Запись выше про «qwen36-35b-a3b-think, таймаут 90 с» устарела и противоречила
фактической конфигурации. Замер на живом LiteLLM владельца:

- `qwen36-35b-a3b-think` расходует весь бюджет токенов на рассуждения и
  возвращает **пустой** `content` — для structured output не пригоден;
- `qwen36-35b-a3b-no-think` отвечает валидным JSON за ~0.5 с, полный
  round-trip `/ai/draft` — ~1 с.

Поэтому: модель `qwen36-35b-a3b-no-think`, `LLM_TIMEOUT_SECONDS=15` (штатное
значение, поднимать не требуется), `temperature=0` в запросе к провайдеру
`openai`.

Температура зафиксирована не ради экономии, а ради детерминизма
категоризации: без неё одна и та же заметка получала разные имена нового
проекта (3–4 варианта за 5 прогонов), и повторный черновик создавал дубликат
проекта. Для провайдера `anthropic` параметр не задаётся: замеренная
нестабильность относится к self-hosted пути, а менять работающий путь без
данных незачем.

## Альтернативы

Tool-use для категоризации — избыточно; сырой JSON-парсинг — хрупче structured outputs.

## Последствия

Ключ API живёт только в env на сервере. Тесты мокают `ai._call_model` — сеть в тестах
не используется. Смена модели не требует изменений кода.
